# Play Console "새 앱 만들기" 등록 가이드

Play 개발자 계정 인증이 끝난 뒤, **Console에 실제로 입력할 값**을 순서대로
모아 둔 문서다. 값은 그대로 복사해 붙여 넣으면 된다.

전체 런칭 흐름(키스토어·AdMob·AAB 빌드)은
[PLAY_STORE_LAUNCH.md](PLAY_STORE_LAUNCH.md)를 본다. 이 문서는 그중
**7단계(Play Console 등록)** 만 상세히 푼 것이다.

---

## 0-A. 개인 개발자 계정에서만 걸리는 것

| 항목 | 개인 계정 | 조직(사업자) 계정 |
|---|---|---|
| D-U-N-S 번호 | **불필요** | 필요 |
| 프로덕션 바로 출시 | **불가** — 비공개 테스트 12명×14일 선행 | 가능 |
| 스토어에 공개되는 개발자 정보 | 이름 + 이메일 (+ 주소) | 회사명 + 이메일 + 주소 |

- **D-U-N-S 번호는 개인 계정에 필요 없다.** 조직 계정 얘기라 혼동하기 쉽다.
- **개발자 연락처가 스토어 페이지에 공개된다.** 개인 계정이면 집 주소가
  그대로 노출될 수 있으니, 등록 전에 개발자 계정 → **개발자 프로필 → 연락처
  정보**에서 무엇이 공개되는지 확인한다. 주소 공개가 부담되면 사서함이나
  비상주 사무실 주소를 쓰는 방법이 있다.
- 프로덕션까지 **최소 2주**가 걸린다는 뜻이므로, 테스터 모집을 오늘 시작한다.

- 미국 수출법 준수

### "광고 제거"를 팔아도 무료 앱이다

Play Console의 **무료/유료는 앱을 내려받을 때 돈을 내는가**만 가리킨다.
앱을 받은 뒤 앱 안에서 결제하는 것(광고 제거 등)은 **인앱 구매**로, 앱은
계속 "무료"이고 스토어에 "인앱 구매" 배지만 자동으로 붙는다.

**무료 → 유료 전환은 영원히 불가능하다**(유료 → 무료는 한 번 가능). 그래서
지금은 무조건 **무료**로 등록해야 한다.

나중에 광고 제거 상품을 붙일 때 할 일(앱 재등록은 필요 없다):

1. Play Console 결제 프로필(판매자 계정) 등록 — 은행·세금 정보, 승인에 며칠
2. 수익 창출 → 제품 → **인앱 상품** → 관리형 상품(1회 구매) 생성
3. **콘텐츠 등급 설문 재제출** — "디지털 구매"를 **예**로 변경
4. "광고 포함" 선언은 **예** 유지(결제하지 않은 사용자에겐 광고가 나온다)
5. 앱에 `in_app_purchase` 연동 + 구매 시 배너·동영상 광고를 모두 숨김

> 수수료는 현재 기준 연 매출 100만 달러까지 15%, 초과분 30%다.

## 4. 출시 (프로덕션 또는 테스트)

### 개인 개발자 계정이면 — 비공개 테스트가 먼저다

**2023년 11월 13일 이후에 만든 개인 계정**은 프로덕션에 바로 못 낸다.
먼저 **비공개 테스트를 테스터 12명 이상 × 14일 연속**으로 돌린 뒤
"프로덕션 액세스 신청"을 해야 한다.
(사업자/조직 계정이거나 그 이전에 만든 계정은 해당 없음.)

> 원래 20명이었다가 2024년 12월에 12명으로 완화됐다. **숫자·기간은 바뀔 수
> 있으니 Play Console 대시보드의 "프로덕션 액세스 신청" 화면에 표시된 실제
> 조건을 기준으로 삼는다.**
> 공식 안내: https://support.google.com/googleplay/android-developer/answer/14151465

지켜야 할 것:

- **내부 테스트(Internal testing)는 조건에 안 들어간다.** 반드시
  **비공개 테스트(Closed testing)** 트랙이어야 한다.
- 테스터는 **Google 계정 이메일**이어야 하고, **실제로 옵트인해서 14일 내내
  유지**해야 한다. 중간에 빠지면 카운트가 끊긴다.
- 12명은 **동시에** 채워져 있어야 한다. 8명으로 시작해 나중에 4명을 더하면
  그 시점부터 14일을 다시 센다.
- 테스터 관리는 이메일 목록보다 **Google 그룹**이 편하다(사람이 바뀌어도
  트랙 설정을 안 건드려도 된다).

절차:

1. 테스트 → **비공개 테스트** → 트랙 만들기
2. `app-release.aab` 업로드 + 출시 노트 작성
3. 테스터 탭 → 이메일 목록 또는 Google 그룹으로 12명 이상 등록
4. **옵트인 링크**를 복사해 테스터에게 전달 → 각자 링크로 참여 후 설치
5. 14일 뒤 대시보드에 **프로덕션 액세스 신청** 버튼이 열린다
6. 신청서에 테스트 중 받은 피드백과 반영 내용을 적어 제출 → 검토 대기

> 신청서는 형식적인 문항이 아니다. "테스터에게 무엇을 물었고, 어떤 피드백을
> 받아, 무엇을 고쳤는지"를 구체적으로 적어야 통과가 쉽다. 테스트 기간에
> 피드백을 실제로 받아 두는 게 핵심이다.

## 5. 심사에서 자주 걸리는 것 (미리 피하기)

| 위험 | 대응 |
|---|---|
| 개인정보처리방침 URL이 404 | 등록 전 브라우저로 직접 열어 확인 |
| 데이터 보안 양식이 실제 SDK 동작과 다름 | AdMob 항목(위치·광고 ID·앱 상호작용) 반드시 포함 |
| "공식", "정부 제공" 같은 표현 | 쓰지 않는다. 데이터 **출처**가 공공기관이라고만 적는다 |
| 다른 앱 이름 언급 | 설명·스크린샷에 경쟁 앱 이름을 넣지 않는다 |
| 스크린샷에 기기 프레임·과장 문구 | 실제 화면 그대로 올린다 |
| 예보를 단정적으로 표현 | "100% 정확", "실시간" 같은 표현을 피한다 |
| 안전 관련 고지 누락 | 자세한 설명에 "출항 전 기상특보 확인" 문구가 이미 들어 있다 — 지운다면 다시 넣는다 |

## 6. 출시 후

- 스토어 URL이 `https://play.google.com/store/apps/details?id=com.badamobile.bada_mobile`
